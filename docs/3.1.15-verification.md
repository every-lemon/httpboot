# 3.1.15-beta.1 verification

The current public suite passes 166 tests. Final package, fresh-clone and clean-image
qualification results are recorded in the release verification asset.

Regression checks cover nonblocking bounded TLS handshakes on Server and Builder,
fresh domain certificates, interrupted recovery promotion preserving the working
EFI files, and beta/RC/final Debian version ordering. Existing tests cover device
approval, account authorization, session fencing, atomic saves, recovery and media.

cold boots remain separately unverified. No physical Client restart is forced.

The records below describe earlier versions; they are retained for migration context.

### Development 9 login and Wi-Fi follow-up

The boot network launcher waits for its terminal-owning child, including when setsid forks. Wireless adapter enablement, scanning, password validation, and association failures have explicit stages. A real PTY test exercises the network-action, SSID, and password dialogs. Physical adapter interaction remains a separate check.

The background saver waits for the authenticated login restore barrier. PAM identifies individual local logins so a console and graphical login on the same Client share one persistent Server session; only the last local logout saves and releases it. Another Client still cannot acquire that session. Failed releases preserve the RAM session for retry. Worker reports include exception class and source-code location, excluding raw exceptions and private paths.

Existing private snapshots passed a read-only restore audit without modifying the live snapshots or sessions. Reported physical login/menu failures need confirmation using the replacement image; the earlier Server reports did not retain the exact exception.

The first development 9 image run authenticated its test account and restored its document, then failed the save check while the test Server reported SQLite lock contention. Server account/certificate/catalogue reads now use query-only WAL read transactions, while mutations retain immediate write transactions and durable commits. A concurrent-writer regression verifies that authentication reads remain available and never observe uncommitted permission changes. The image must be requalified against this fix before publication.

After the WAL fix, the private-image test authenticated, restored, and committed its document successfully. Its shared three-minute login/save/logout timer expired during logout on the file-backed-memory test machine. Qualification now starts a fresh bounded three-minute timer only when the login workflow advances to a new stage, retaining the overall boot deadline and all session-release and snapshot assertions.

Final development 9 qualification passed native UEFI HTTP pairing, authenticated desktop startup, PAM account login, document restore/save, logout with Server session release, and verified offline graphical recovery. The private repair image was published with the preceding private image retained for rollback. Served bootstrap hashes, authenticated range downloads, account preservation, and both Server menus were checked after publication. Physical Wi-Fi and user login still require confirmation on the affected Client.
